SIMULATOR No adapter. No car. Every number this API serves is generated by simulator/model.py — simulated, not a reading from any vehicle, and a green simulator run is not evidence about a real one.

Ha-Kake simulator — control API This port drives the model. The cockpit that looks like the car is the dashboard's /sim page.

Cockpit: open the cockpit on the dashboard — the dashboard's /sim page pointed at this API with ?control=.

Start the cockpit

Either command starts the simulated car and the dashboard whose /sim page is the cockpit. The first is the usual one; the second is this rig, over a pseudo-terminal, starting the dashboard itself:

python web/app.py --adapter sim --port 5055
python hakake_sim.py --pty --scenario drive --launch-dashboard

Both print the dashboard, cockpit and control-API URLs. Add ?dashboard=5055 (or a full URL) to this page's address and the link above appears.

The API, from a shell

  • /sim/schema — every knob: type, unit, range, default, label, category
  • /sim/state — the model's current state
  • /sim/record — the state in the dashboard's own vocabulary (501 when this core cannot)
  • /sim/knobs, /sim/faults, /sim/scenarios, /sim/info

Every knob the schema lists is settable; nothing is reserved for the cockpit:

curl -s localhost:PORT/sim/schema | jq '.knobs | keys'
curl -s -X POST localhost:PORT/sim/knobs -H 'content-type: application/json' -d '{"soc": 15}'
curl -s -X POST localhost:PORT/sim/scenario -H 'content-type: application/json' -d '{"name": "drive"}'
curl -s -X POST localhost:PORT/sim/step -H 'content-type: application/json' -d '{"sim_seconds": 3600}'
curl -s -X POST localhost:PORT/sim/reset

A typo in a knob name comes back 400 with near matches under suggestions; numbers clamp to the schema's range. {"name": ""} to /sim/scenario clears the scenario and the model free-runs.
